# クイズで巡る東大本郷

現在のバージョンは **3.1** です。HTML・CSS・JavaScriptで構成され、GitHub Pagesや一般の静的ウェブサーバーで動作します。
全7地点で1文字ずつ集めます。問題の原稿は運営用のExcelで管理し、地点ごとの静的ファイルに書き出します。

## QR読み取りと完成演出

### QRコード読み取り（文字一覧＋解答ページ7件）

- 画面の「次のQRコードを読み取る」ボタンから、カメラの読み取り画面を開きます。
- ブラウザにカメラ許可を求め、可能なら背面カメラを使用します。
- 対応するQRコードを認識すると、該当する解答・解説ページへ自動で移動します。ページを開いた時点で文字が記録されます。
- **同じ公開先の回答ページ形式に一致し、対応するクイズデータを取得できるQRコード**を受け付けます。
- カメラの使用を拒否した場合やカメラがない場合は、QRコードを写した画像を選ぶ「写真から読み取る」も利用できます。
- 閉じる操作、画面を離れる操作、ブラウザのタブを非表示にする操作でカメラを停止します。再開には「カメラを再試行」を押します。
- カメラ映像や選択した写真をサーバーに送信しません。解析は端末内のJavaScriptで行います。

**ライブラリの読み込みについて：** QRコード解析には [jsQR v1.4.0](https://www.npmjs.com/package/jsqr)（Apache-2.0）を使用します。配布ファイルとライセンスは `js/vendor/jsqr-1.4.0/` に同梱しています。新サーバーに配置するときは、このフォルダーも含めてコピーしてください。jsQRを読み込めない場合、対応ブラウザでは `BarcodeDetector` を代替使用します。どちらも利用できない場合はその旨を画面に表示します。

### 文字をすべて集めたときの演出

- 最初に7つの文字がそろった後、文字一覧を開いた時に風船が画面下から上へ飛ぶ演出を**1回だけ**表示します。
- 完成後、文字カード7枚に淡い黄色・金・水色・白のグラデーション背景（現在の配色）を適用します。
- カードごとにタイミングをずらし、斜め方向の光沢がゆっくり横切るCSSアニメーションを継続表示します。
- 未完成の場合は通常のカード表示で、アニメーションはしません。
- 端末側で「視差効果を減らす」などが有効な場合（`prefers-reduced-motion: reduce`）、風船を省略し、カードは静的なホログラム風表示にします。

## 公開URLと進捗の保存

GitHub Pagesの公開URLは `https://yamada-masayuki.github.io/quiz/` です。現在の公開URLを維持する場合は、手元のQRコードのリンク先が一致していれば引き続き使えます。

進捗と初回の完成演出は同じブラウザのローカルストレージに保存します。公開URLのプロトコル・ホスト・ポートが同じで、本番用の保存キーを維持する場合、上書き更新後も同じブラウザで進捗を引き継ぎます。ドメインやブラウザ、端末を変えると新しい記録として始まります。記録が難しい場合は、参加案内の裏面に文字と番号をメモして最終問題に参加できます。

## ファイル構成

- `index.html`：一覧・収集状況・完成画面
- `qr/answer_{地点ID}_{ランダム4字}.html`：各QRコードの解答・解説ページ（7件）
- `js/config.js`：共通設定と各地点のID・地点名・表示用番号
- `js/routes.js`：回答URLの形式と組み立て
- `data/`：地点ごとの問題・正解・解説・文字・写真の情報
- `js/progress.js`：発見した文字と回答URLの識別子の記録・読み出し
- `js/index.js`：一覧と進捗の描画、完成判定
- `js/answer.js`：各解答ページの内容・訪問記録
- `js/qr-scanner.js`：カメラ操作、写真からの読み取り、URL形式とクイズデータの確認、ページ遷移
- `js/celebration.js`：文字発見時の紙吹雪、風船アニメーションと初回実行フラグ
- `js/guide.js`：「説明を見る」の参加案内
- `js/exploration-map.js`：クイズスポットのマイマップ
- `js/vendor/jsqr-1.4.0/`：同梱のQR読み取りライブラリとライセンス
- `css/style.css`：共通画面、カメラUI、ホログラム・風船アニメーション
- `assets/images/`：地点別のイラストなどのSVG
- `assets/photos/`：解説ページの写真
- `docs/`：テスト用ポスターPDF

## 設置地点とQRコード

掲示用QRコードは、設置先の公開URLと `qr/` 内の既存の回答ファイルを使って作成します。掲示前に7枚を読み取り、それぞれ対応する解答ページを確認してください。

`docs/` のポスターPDFはGitHub Pages用のテスト資料です。別の静的サーバーへの配信には、掲示用QRコードとクイズ本体のファイルを使います。

## 公開・更新手順

- **GitHub Pages** は `main` への変更を `.github/workflows/static.yml` で配信します。GitHubのActionsで実行結果を確認し、公開ページを再読み込みします。
- **別の静的サーバー** では、リポジトリのZIPを展開し、`quiz/` 内の本体ファイルを設置します。テスト資料の `docs/` は設置対象から外します。配置先が `/utokyo-quiz/` なら、`/utokyo-quiz/index.html` が一覧の入口です。`css/`、`js/`、`qr/`、`data/`、`assets/` の階層とファイル名を保ちます。リンクは相対パスで、ビルドやアプリ設定の変更は不要です。
- サイト内のカメラを使う場合はHTTPSで配信します。iPhoneのSafariとAndroidのChromeなどで、実際に掲示する7枚のQRを読み取って、答え合わせ、文字と番号の表示、`7 / 7` 時の最終問題の案内を確認します。
- 古い表示が残る場合はページを再読み込みします。進捗を保持したい場合は、サイトデータ全体の削除を避けてください。

## 確認項目

1. 文字一覧の「次のQRコードを読み取る」を押すと、読み取り画面が開く。
2. カメラを許可すると背面カメラの映像が出る。
3. 7個のQRコードのどれを読み取っても該当する解答ページに移動し、自動で1文字が解放される。
4. 解答ページ内の同ボタンからも、次のQRコードを読み取れる。
5. 許可を拒否しても「写真から読み取る」は利用できる。
6. 読み取り画面を閉じるとカメラが停止する。
7. 7文字完成後の一覧ページで風船が上昇し、再読み込みでは再表示されない。
8. 完成後は7枚のカードの背景がゆっくりきらめき続ける。
9. 未完成ではカードのアニメーションが表示されない。

> ブラウザからのカメラ利用は原則HTTPSが必要です（`localhost` は開発用の例外）。`file://` で開く方式は推奨しません。カメラが使用できるかどうかは、端末・ブラウザ・許可設定に依存します。

## 発見演出とテスト用の進捗初期化

新しい文字を記録したとき、解答ページに添付素材の4色の扇形が広がります。再訪問時と、視差効果を減らす設定では省略します。

3.1では保存キーを `todai-hongo-quiz-progress-production-v2` に切り替えます。旧キーの履歴は端末に残りますが、3.1は新しい記録の `0 / 7` から始まります。テストで3.1の進捗と完成演出を初期化するには、ブラウザの開発者ツールで次を実行して再読み込みします。

```javascript
// 進捗と初回風船表示フラグの両方を消去する
window.QuizProgress.clear();
```

すでに7文字完成していて、風船だけを再確認したい場合は `localStorage.removeItem('todai-hongo-quiz-progress-production-v2-celebration-seen-v1')` を実行して一覧ページを再読み込みします。

## Excel原本の管理と書き出し

原稿は「本郷いちょう遊歩クイズ確定（回答）.xlsx」と、その後に公開版へ反映した修正をもとにしています。初回に現行版から編集用のExcelを作り、以降はそのExcelを運営側で管理してください。ファイルはリポジトリと公開先の外に置きます。

1. リポジトリのルートで `python3 -m pip install openpyxl` を実行します。
2. 初回だけ `python3 scripts/quiz_workbook.py export ../quiz-master.xlsx` を実行します。
3. Excelの「フォームの回答 1」シートで各地点の問題、正解、解説、文字、番号などを編集します。写真と説明文は「写真」シートで編集します。行を移動しても、`地点ID` は既存の回答URLに対応する固定値のままにします。
4. `python3 scripts/quiz_workbook.py build ../quiz-master.xlsx` を実行します。全地点の入力、番号の重複、画像ファイルの存在を確認してから、変更のある公開ファイルを書き出します。Gitの差分を確認し、公開には生成済みの `quiz/` を使います。

回答ページを開くと、そのURLのランダム部分と文字が地点ごとに `localStorage` に記録されます。文字一覧は、保存した文字を発見順で表示し、保存したランダム部分から振り返りリンクを作ります。文字を修正した地点は、回答ページを開き直すと保存済みの文字も更新されます。

問題、正解、解説、文字は回答ページごとに読み込みます。公開済みの各回答ページとそのデータは、URLを知っていれば閲覧できます。

## クイズスポットの地図

全8ページの右下にある「地図を見る」ボタンから、クイズスポットのGoogle マイマップを開けます。上部の「Google マップで本郷キャンパスを開く」リンクから、クイズスポットのマイマップを開けます。地図は画面サイズに合わせて表示され、下部にGPSと建物への立ち入りに関する注意書きがあります。発見した文字は文字一覧で確認できます。

## 参加案内とフッター

各ページの「説明を見る」では、スマートフォンの準備、青い風船を目印にしたクイズスポットの探し方、正門または伊藤国際門での最終問題への参加方法を案内します。説明の外側をクリックまたはタップすると閉じます。

フッターには「クイズで巡る東大本郷」「東京大学本郷いちょう遊歩学生ボランティア一同」「東京大学本部社会連携推進課」を表示します。

## カラーデザイン

黄色 `#FFCC00` を見出し・達成表現、濃い青 `#0868B3` を操作ボタン、クリーム `#FFFCF2` を背景に使用します。本文は濃色、リンクは濃い青で読みやすさを確保しています。文字カード、QR読み取り画面、解答ページ、完成時のカードと風船も共通配色です。参考キービジュアルの画像自体は同梱していません。

## 読み取り成功のフィードバック

QRコード認識成功時はカメラを停止し、「読み取り成功！」を表示して約1秒後に解答ページへ移動します。カメラ・写真の両経路で共通の処理を使い、待機中の重複認識を防ぎます。閉じる／Escapeで遷移をキャンセルできます。解答ページの読み取りボタンは文字獲得ブロックの外に配置しています。強調ボタンは白い文字と枠、読みやすい濃い青の背景を使用し、地図ボタンには線画アイコンを追加しています。

## 発見順と最終問題

- 文字一覧は初めて発見した順に並び、未発見の枠は「？」で表示します。再訪問しても順序は変わりません。
- 発見済みカードと解答ページでは、文字の左に確定版の対応表に従った丸囲みの番号を表示します。番号は各地点の文字に固定されます。番号の設定には `keywordNumber` を使います。
- 「発見した文字」は画面幅によらず1行3文字で表示し、発見済みカードに「発見！」と表示します。画面上の並べ替え操作はありません。参加者は現地の案内で示される順番で文字を読み、最終問題のヒントにします。
- 新しい発見は一覧の末尾に追加します。別タブで発見した場合や、ブラウザの「戻る」で一覧に戻った場合も、保存済みの記録を読み直します。
- 文字一覧の上部では、7文字を集めたら正門または伊藤国際門にいる学生スタッフの最終問題に挑戦するよう案内します。
- 7文字発見時の表示：
  - 全部の文字を発見しました！
  - 正門または伊藤国際門にいる学生スタッフが持っている最終問題に挑戦しましょう。見つけた文字がヒントになります。最終問題に正解するとオリジナル修了証書をプレゼント！
- 初回の風船演出と完成カードの光沢は継続します。

確認項目：順不同の発見と再読み込み、同じQRの再訪問、既存履歴の引き継ぎ、未発見枠、3列表示、並べ替えボタンがないこと、7文字発見時の案内、文字一覧と解答ページの表示番号が確定版の対応表と一致すること。
